# Публичные аудиты: инструкция редактора

## Что создаём

Один материал в Payload CMS = одна публичная страница по адресу:

`/audits/<slug>`

После сохранения аудит попадает в каталог `/audits`, если флаг **«Скрыто»** выключен. В каталоге карточка показывает только обложку, дату, заголовок и краткое описание.

## Перед началом

Подготовьте:

- заголовок, дату публикации и URL-идентификатор;
- обложку 1280 × 720 px или больше;
- короткое описание для карточки и поисковой выдачи;
- данные для hero: проект, тикер, сайт, вердикт, сильную и слабую стороны, рейтинг и метрики;
- оценки по блокам методологии; веса в сумме должны составлять 100%;
- текст аудита, таблицы, графики и ссылки на источники;
- SEO-метаданные и OG-изображение, если обложка не подходит для соцсетей.

Не публикуйте инвестиционные рекомендации, обещания доходности или формулировки о гарантированном результате. На странице автоматически выводится дисклеймер: аудит не является инвестиционной рекомендацией.

## Шаг 1. Создайте запись

1. Откройте `/admin`.
2. В меню **Аудиты** выберите **Публичные аудиты** → **Создать**.
3. Заполните:
   - **Заголовок** — полное название материала. Его видят в карточке и он используется в SEO по умолчанию.
   - **Slug** — латиницей, в нижнем регистре, через дефис. Например: `my-project-tokenomics-audit`.
   - **Дата публикации** — дата на карточке и странице.
   - **Краткое описание** — 1–3 предложения: главный вывод и контекст. Не дублируйте заголовок.

**Что увидит посетитель:** в `/audits` появится карточка с датой, обложкой, заголовком, описанием и ссылкой `View`.

## Шаг 2. Загрузите обложку

В поле **Изображение** выберите существующее медиа или загрузите новое.

Для новой загрузки в разделе **Медиа** обязательно заполните **Alt текст**: коротко опишите изображение и проект, например: `Иллюстрация аудита токеномики My Project`.

Рекомендуемый формат: WebP или PNG, горизонтальное изображение 16:9, без мелкого текста по краям. Обложка используется в карточке каталога; если её нет, сайт покажет абстрактную заглушку.

**Что увидит посетитель:** обложка занимает верхнюю часть карточки в каталоге.

## Шаг 3. Заполните шапку аудита

Раскройте группу **Шапка (Hero)** и заполните:

| Поле в админке | Что вывести на странице |
| --- | --- |
| Компания (Кому) | Справочная информация о проекте; полезна для редакции и схемы страницы |
| Токен ($TICKER) | Крупный заголовок hero |
| Стандарт | Справочная информация, например `ERC-20` или `TON` |
| Описание проекта | Абзац под заголовком |
| Сайт | Кликабельная ссылка на сайт проекта |
| Короткий вердикт | Первый тезис в блоке сильных/слабых сторон |
| Сильная сторона (+) | Позитивный тезис в этом же блоке |
| Слабая сторона (−) | Главный риск или ограничение |
| Буквенный рейтинг | Метка рейтинга, например `BBB` |
| Балл (0–100) | Число рядом с буквенным рейтингом |

В **Метрики (Hero)** добавьте только актуальные показатели. Каждая строка — название и уже отформатированное значение: `FDV` → `$120M`, `TVL` → `$18.4M`. Не передавайте формулы или необъяснённые сокращения.

**Что увидит посетитель:** тёмную шапку с тикером, сайтом, рейтингом, описанием, кнопкой скачивания PDF и лентой метрик; ниже — вердикт, сильная и слабая стороны.

## Шаг 4. Заполните рейтинг по методологии

В блоке **Рейтинг по методологии 8Blocks** добавьте по строке на каждый оцениваемый блок:

- **Блок** — название критерия;
- **Вес (%)** — вклад критерия в итог;
- **Score (0–5)** — оценка с точностью до двух знаков при необходимости.

Проверьте перед сохранением:

- сумма весов — ровно 100%;
- оценка — в диапазоне 0–5;
- балл в hero соответствует расчёту по строкам либо сознательно утверждён как финальный.

Сайт переводит оценку `0–5` в шкалу `0–100`, строит радарную диаграмму, полосы по критериям и таблицу с вкладом каждого критерия. Если поле **Балл (0–100)** в hero заполнено, именно оно показывается как финальный балл; при этом таблица продолжает считать итог из строк. Несовпадение будет заметно пользователю.

## Шаг 5. Соберите содержание

В поле **Содержание** используйте логичную структуру:

1. Контекст и данные на дату аудита.
2. Методология и источники.
3. Анализ ключевых блоков.
4. Риски, ограничения и возможные улучшения.
5. Итог.

Используйте заголовки `H2` для главных разделов и `H3` для вложенных. При двух и более заголовках сайт сам добавит содержание страницы.

Доступные специальные блоки:

- **Выделенный блок** — важное или критическое замечание;
- **Таблица** — для сравнений и структурированных данных;
- **График** и **Строка графиков** — для временных рядов, распределений и сравнений;
- **Полоса метрик**, **Статистические колонки**, **Инфо-колонки** — для компактных показателей;
- **Чек-лист**, **Нумерованные примечания**, **Профиль рисков** — для выводов и рисков;
- **Встраивание (iframe)** — только для доверенных embed-URL с понятным заголовком и высотой.

Изображения внутри текста загружайте через **Медиа** и заполняйте для них alt-текст. Для графика добавляйте текстовое описание данных в медиа — оно не показывается на странице, но делает материал понятнее для AI-систем.

## Шаг 6. Добавьте эксперта и связанную статью

В группе **Эксперт** выберите автора. Имя, должность, фото и LinkedIn подтягиваются из его карточки; вручную их в аудит не дублируйте. Поле **Рейтинг эксперта** необязательно.

Если есть развёрнутая статья в блоге:

1. укажите её в поле **Статья в блоге**;
2. заполните **Текст CTA**.

CTA показывается на странице только когда заполнены оба поля.

## Шаг 7. Заполните SEO

В группе **SEO**:

- **SEO заголовок** — до ~60 символов; если оставить пустым, берётся заголовок аудита;
- **SEO описание** — до ~155 символов; если оставить пустым, берётся краткое описание;
- **OG title / OG description** — версия заголовка и описания для превью в соцсетях;
- **OG изображение** — используйте, если для соцсетей нужна отдельная картинка; иначе применяется обложка;
- **Скрыть от поисковиков (noindex)** — включайте только для чернового, тестового или юридически ограниченного материала.

## Шаг 8. Проверьте и опубликуйте

Перед публикацией откройте в новой вкладке:

1. `/audits/<slug>` — проверьте hero, содержание, графики, итоговый рейтинг, CTA и мобильную вёрстку.
2. `/audits` — проверьте карточку, дату, порядок и обложку.
3. Ссылку из кнопки PDF — убедитесь, что документ скачивается.

После проверки убедитесь, что флаг **Скрыто** выключен, и сохраните запись. Для снятия с сайта включите **Скрыто**: аудит исчезнет из каталога, sitemap и публичной ссылки.

## Как работает порядок в каталоге

Сначала показываются записи с флагом **Закрепить в начале**, затем остальные — от новой даты публикации к старой. На странице помещается 9 аудитов; остальные доступны через пагинацию.

## Мини-чек-лист перед публикацией

- [ ] Заголовок, slug и дата заполнены.
- [ ] Обложка и alt-текст добавлены.
- [ ] Краткое описание объясняет вывод без кликбейта.
- [ ] Hero заполнен, рейтинг и сумма весов проверены.
- [ ] Содержание имеет H2/H3, ссылки и подписи к данным.
- [ ] SEO и OG-поля заполнены или осознанно оставлены на значениях по умолчанию.
- [ ] Аудит открыт на десктопе и мобильном экране.
- [ ] Флаг **Скрыто** выключен.

## Скриншоты для этой инструкции

Нужно сделать два снимка на примере одного опубликованного аудита:

1. **Админка:** экран редактирования с видимыми полями «Заголовок», «Slug», «Краткое описание», «Изображение» и раскрытой группой «Шапка (Hero)». Подпись: «Основные поля записи: они формируют карточку в каталоге и шапку страницы».
2. **Публичная страница:** каталог `/audits` с карточкой этого же аудита и затем его страница `/audits/<slug>` с hero. Подпись: «Карточка берёт обложку, дату, заголовок и краткое описание; hero — данные из группы “Шапка”».

Не используйте на скриншотах токены доступа, персональные email, черновые ссылки или внутренние заметки.
