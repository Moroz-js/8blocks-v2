# Обложки событий: однократный импорт в Payload

Изображения из макета загружаются в `media`, а не встраиваются в клиентскую сборку. Обложка карточки — `events.cover`; отдельный постер детальной страницы остаётся приоритетным. Фото страны — `mapPhoto` у офлайн-события. Карта использует самое свежее из прошедших событий с заполненным фото для этой страны, иначе — обложку. Файлы `src/widgets/EventsHub/assets/*.webp` нужны для первичного импорта, не для показа на сайте.

**Важно:** обе staging-сборки используют EN production DB, а файлы `/api/media/file` проксируются на EN production. Не загружать файлы в каталог staging при общей БД. Импорт выполнять только на инстансе-владельце медиатеки с подтверждённой целевой БД, либо в полностью изолированной копии. До начала сохранить резервную копию БД и uploads. Схема `20261126_000000_event_map_photo` должна быть применена. Не подключать импорт к автодеплою. Для рабочей выкладки согласовать окно: схема → импорт → переключение интерфейса, чтобы не показать старые обложки между шагами.

Из каталога проекта с правильным `.env` и `public/uploads`:

```sh
node --env-file=.env -r ./scripts/payload-next-env-shim.cjs -r tsx/cjs scripts/import-event-artwork.ts
```

Это **предпросмотр**, без записей. Проверить хост и имя БД, путь медиатеки и все 12 строк, сохранить `before` для восстановления. Для переводных записей проверяется исходный slug или alternateSlug; при их отсутствии проверяется единственное событие той же даты и формата. Перед применением сверить заголовки. Неоднозначное или отсутствующее соответствие останавливает импорт. Для применения повторить команду с `--apply`; если подтверждена замена уже заполненных полей, дополнительно передать `--replace-existing`. Не запускать одновременно из двух процессов. При сбое возможен частичный импорт: сверить журнал и повторить предварительный просмотр. Уже связанные файлы пропускаются.

Проверка EN/AE: 8 обложек, 4 фото (DE/ES/KR/SG); RU: 4 совпадающих события, 3 фото (DE/KR/SG). Московский форум не входит в набор. URL файлов открываются; повторный предпросмотр показывает соответственно 12 или 7 `unchanged`. После редакторских правок импорт повторять не нужно. Для восстановления вернуть только изменённые связи к `before` (в том числе `null`); не удалять другие файлы и записи медиатеки. Тексты и статусы событий не импортируются.
